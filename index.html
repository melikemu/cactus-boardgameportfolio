Digital Strategy Game

A board game designed for physical production in 2014, reaching players digitally in 2026. A decade-long production constraint solved by moving to the browser — with AI-assisted development, real-time multiplayer, and a full analytics pipeline.

Origin

CACTUS started as a wooden board game — a 3D spatial strategy game for two players. In 2014 it reached the finals of the IMMIB national design competition and was exhibited in the official catalogue. In 2018 it was shown in the main hall of the 87th İzmir International Fair. Not a design fair — an international trade exhibition.

Then it stalled. Tooling cost for wooden board game production at commercial scale was prohibitive. 3D printing was tested; small batches were produced, the game was playable, but unit economics never cleared. The design sat for over a decade with no viable path to reach players.

The constraint wasn't the game. It was the medium.

In 2026, a browser-based implementation removed every friction point that blocked the physical version. No manufacturing, no inventory, no retail. A game that couldn't ship for ten years ships as a link.

Development Model

This project was built with AI as the primary implementation tool. Claude generated all production code — Three.js rendering, game logic, Firebase integration, mobile gesture handling, cross-browser fixes. No line of code was written by hand.

That shifts the entire weight of the work to decisions. What should the gesture model be? What is the correct definition of an unbroken sequence in 3D space? When does a continuity bonus trigger, and when should it not? Which analytics events carry signal? The AI cannot answer those questions. They require product judgment, design experience, and domain knowledge.

Design Decisions

Mobile gesture model — separating exploration from commitment
On desktop, mouse hover lets users explore positions before placing. On mobile, every touch is simultaneously a hover and a tap — the initial implementation treated any tap as a placement trigger, which broke exploratory flow entirely. The fix: one-finger drag updates a ghost preview in real time, placement only fires on explicit confirmation, and only when the position is valid. Mobile experience became equivalent to desktop, not a degraded version of it.
Accessibility — WCAG AA/AAA as Definition of Done
A color-heavy 3D game risks failing basic readability under color vision deficiencies. Rather than retrofitting, WCAG AA/AAA contrast ratios were set as non-negotiable DoD criteria from the start. A separate Material Lab was built to simulate five color vision conditions across 24 material combinations, enabling testable, defensible color decisions before applying them to the main build.
Analytics — events, not page views
Standard page-view analytics are meaningless for a single-page game. A session that starts and ends on the same URL could be a 30-second bounce or a 25-minute match. The instrumentation treats the game as a stateful session: every meaningful state transition — piece placed, game abandoned, board inspected, replay started — is captured with full context. The full game is stored as a structured move notation, enabling analysis at the move level.
Decision Rationale
Single HTML file, no bundler Zero deployment friction. Shareable via URL, playable within seconds of receiving a link. Eliminates onboarding as a conversion risk.
AI for implementation, human for all decisions Preserves product and UX judgment where it matters. Speed of execution without delegating the decisions that determine quality.
Online multiplayer via Firebase Removes the physical colocation constraint that blocked the game for a decade. Two players anywhere can complete a match. This is the primary product unlock.
Penalty scoring for unused pieces Closes a game theory gap — without it, conservative piece hoarding is a dominant strategy. Deducting unused piece units forces a real trade-off.
Minimum viable UI system CSS custom properties and spacing rhythm only — no component library. UI debt was explicitly accepted and documented so it wouldn't block core gameplay progress.

Positioning

CACTUS sits between Checkers and Chess in game tree complexity — approximately 10³⁸ possible game states. This is a consequence of three-dimensional placement, 24 rotation states per piece, and the absence of piece repetition. The game's depth was not incidental; it was designed in 2014 and proven by analysis in 2026.

This project demonstrates what happens when a design that has already proven its quality is freed from the medium that was limiting it. The work was not inventing the game — it was removing every obstacle between the game and the people who should be playing it.
